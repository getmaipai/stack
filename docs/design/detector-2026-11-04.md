# DETECT-01: one shared object detector (2026-11-04)

## Goal

Give MaiPai Home one Stack-owned detector route usable by image editing, camera events, and an optional generated-picture check. This is a design and benchmark proposal only. It does not wire a caller, change a safety gate, or claim a detector is production-ready. Stack remains loopback-only; Home remains the caller and owns all people-facing policy.

This follows the third-party artifact rule in `docs/RELEASES-AND-DEPENDENCIES.md`: models are downloaded on demand with an exact revision/URL, checksum, and recorded licence; weights are never vendored. Candidate source distributions/licenses must be checked for AGPL compatibility before selection. AGPL-3.0 is compatible with this AGPL-3.0 Stack subject to its obligations, but the licensing of weights and code must be reviewed separately. Ultralytics YOLO code is AGPL-3.0 by default (with a separate commercial license); choosing it means accepting AGPL obligations for the integrated service, not treating the model as permissively licensed. Do not bundle an unreviewed artifact.

COCO-80 has the named common classes person, cat, dog, horse, bird, and car. This is a useful initial vocabulary, not a guarantee of quality. Class mapping and detection thresholds must be reported per class and validated on household imagery. “Animal” can be a caller-side grouping of detected animal labels, not a detector label invented by the Stack.

## Candidate selection criteria

1. License compatibility for both inference code and weights, with exact source and license recorded. Prefer Apache-2.0 candidates for low-friction reuse; AGPL-3.0 is legally compatible with this AGPL Stack but has copyleft consequences for distribution and integration. No licensing inference from a model family name.
2. Download size and runtime resident memory, including provider/runtime overhead; measure both. Small artifact size alone does not predict residency.
3. Measured accuracy by class (hits, misses, false positives) on a fixed, described set, plus confidence and box quality. This small smoke set is not a benchmark of population accuracy.
4. Warm and cold latency, sustained throughput, and memory on the Studio using ONNX Runtime CoreML and CPU. Record provider actually selected; fallback must be visible. Later repeat on intended homelab hardware.
5. Input/output format, preprocessing, postprocessing, export provenance, model revision, and checksum must be reproducible. Avoid claiming CoreML acceleration unless provider logs confirm it.

Candidates for the first bench: Apache-2.0 RT-DETR (small variant), Apache-2.0 YOLOX (nano or tiny), and a YOLO-family model with its precise license stated. The harness is intended to accept locally exported ONNX files so the export source/revision is auditable. D-FINE is another possible Apache-2.0 candidate, but export/runtime compatibility and exact checkpoint licensing must be established before adding it. Ultralytics-produced artifacts are excluded from the permissive shortlist unless AGPL-3.0 obligations are explicitly accepted and reviewed.

## Shared route proposal

`POST /v1/images/detect` takes an image upload (existing Stack image limits apply) and optional `classes` allowlist / `threshold`; response:

```json
{
  "detections": [
    {"label": "dog", "score": 0.94, "box": {"x": 0.12, "y": 0.18, "width": 0.51, "height": 0.63}}
  ]
}
```

Box values are fractions in `[0,1]`, origin at the top-left, with width/height relative to the original image. Labels are canonical lowercase class names. Model identity belongs in the standard Stack identity headers; errors are explicit and never encode a safety verdict. One request returns detections for all requested callers; a caller may filter labels. No tracking, masks, age estimation, or safety decision is part of this route.

For erase, use the box only to seed/crop the existing foreground-instance helper or a small segmenter; intersect/associate its mask with the selected detection and return/use that mask for LaMa inpainting. Measure mask latency, boundary quality, and failure rate separately against the current Apple Vision helper. Do not assume detector boxes are adequate masks. The current `subjectmask.swift` is a useful baseline on macOS, but its availability does not establish Linux behavior.

## Results (measured 2026-11-04, Mac Studio, Apple M5 Max, onnxruntime 1.19.2)

Setup. Harness `backend/scripts/detector-bench.py` (adapters for the three layouts, fixed in this run: the earlier version had a space in the "frisbee" label and assumed decoded YOLOX output; YOLOX raw grid decode, letterbox and NMS are now explicit). Models and images live in `/private/tmp/claude-501/detbench`, outside git. 17 images: 15 COCO val2017 photos with real COCO labels (2 dog, 2 cat, 2 horse, 2 bird, 2 person+dog, 1 person+cat, 1 group of 5 to 9 people, 1 car, 2 with no COCO annotation) and 2 public-domain Wikimedia illustrations (a 1908 Puck cartoon, a dog-and-rabbits postcard) labelled by hand. Threshold 0.4, 640 px input, 3 warmup plus 5 timed runs per image, median per image then median over images (model run only, no pre/post-processing). Peak RSS is the whole bench process.

Animal denominator is 12 animal-in-image cases (dog 5 including the cartoon dog, cat 3, horse 2, bird 2). Every model got person 5/5, car 1/1. Misses: YOLOX missed the dog in one person+dog photo (called it a cat) and its bird box in one image was too loose (IoU below 0.5); YOLO11n missed a dog and a cat at 0.4 and had one loose bird box. False positives seen: bottle, bowl, dining table, truck, tie, cell phone, remote, potted plant and bed. Notable: all three call the rabbits in the dog-and-rabbits postcard "dog" (with scores up to 0.92), so a cartoon animal outside the vocabulary becomes a dog; YOLO11n found a person at 0.5 in one of the two empty photos; the other two models were clean on both. All three found the dog on the 1908 cartoon and a person on the Uncle Sam figure; all three also reported "potted plant" for the cartoon palm.

CoreML. The provider list reported CoreML first, but the graph placement was not inspected, so partial CPU fallback is possible. CoreML was 4x faster for YOLOX-s, 2x for YOLO11n, and slower for RT-DETR (transformer ops, 690 ms cold, 1.2 GB RSS). Accuracy on CoreML matched CPU except YOLO11n losing one bird and YOLOX gaining one false positive (FP16 effects). With 15 labelled photos these numbers are a smoke test, not accuracy.

### Box to outline (step 5)

For the 11 animal photos, the best RT-DETR animal box was matched to the Apple Vision foreground instance (`subjectmask`, VNGenerateForegroundInstanceMaskRequest). Vision returned one instance in 10 of 11 photos and none in 1 (person+cat); IoU with the detector box was 0.93 to 0.98 for 6 of 8 solo-animal photos, 0.70 and 0.59 for the two birds (the second mask includes a leg-like branch piece), 0.77 for one person+dog, and 0.31 for the other person+dog where Vision merged the person and dog into one instance. Opened overlays show clean, tight outlines for dog, cat, horse and bird in the single-animal cases. Conclusion: detector box plus Vision instance (pick the instance by IoU) gives a clean outline when the animal is alone; with a person in contact it can merge, and the box is then the only separator. The dog-and-rabbits postcard produced no Vision instance.

Vision kind labelling (validates `find_subjects`). Vision alone labelled the animal kind "animal" in 0 of 11 animal photos: 10 were labelled "person" and 1 had no instance. The cause is in `subjectmask.swift`: VNGeneratePersonInstanceMaskRequest returns a non-empty mask over dogs, cats, horses and birds (about 190k of 262k mask pixels on a dog photo with no person), so the person test passes first. VNRecognizeAnimals itself found a box in only 6 of the 7 cat/dog photos and 0 of 4 horse/bird photos (it only knows cats and dogs). Fix is in the helper, not here: take person only when the person mask agrees with a person detector box, and use the detector label for the kind. This is a defect in the already landed find_subjects labelling that this bench exposed; no code was changed for it in this task.

## Recommendation

Use a detector for labels and boxes and keep Vision for the outline. First choice: RT-DETR r18vd (Apache-2.0): best on the animal set (12/12, IoU 12/12), no NMS, fewest false positives; costs 105 ms on CPU and 435 MB, and CoreML does not help it, so run it on CPU. If the always-on Frigate budget or memory matters, YOLOX-s (Apache-2.0) on CoreML is 12 ms and 306 MB, with one wrong-class and one loose box in 12. YOLO11n is the fastest and smallest but the weakest here and AGPL-3.0, so only choose it if AGPL obligations are explicitly accepted. Not decided here: Home must set the threshold and the person-helper policy, per-class thresholds are needed (animals were fine at 0.4, background objects were not), and the test must be repeated on household photos and on the homelab CPU before any model ships. Keep Vision for masks and fix its kind labelling as above.

## Frigate and safety integration questions

Frigate has historically supported built-in local detectors and custom external detectors through a detector API, but its current documented API/configuration and supported transports could not be verified because network DNS was unavailable. Before implementation, check current official Frigate docs and version. If external detection is supported over a local HTTP API with the required frame transport, the Stack could provide the common detector; otherwise Frigate's own detector is likely a better fit for its always-on frame pipeline, while the Stack API remains useful for Home's per-request callers. Do not bridge by exposing the Stack beyond loopback or adding an unreviewed network listener.

The generated-picture helper needs a Home-owned contract: which generated-image event invokes it; whether a person detection only requests a second check or can hold/reject output; timeout/error semantics; threshold and uncertainty handling; and how it composes with the existing minor/CSAM check. Stack returns detections only and must not weaken, replace, or short-circuit that check.
