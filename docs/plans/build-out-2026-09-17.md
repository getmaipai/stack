# The Stack build-out: the program

Written 2026-09-17, the day the repo was created. The design is in
[`../dev.md`](../dev.md), the experience in [`../ux.md`](../ux.md), the
seams in [`../integrations.md`](../integrations.md), the items in
[`../BACKLOG.md`](../BACKLOG.md). This file is the order of work, who

## The shape of the work

Milestone 0 ends when the Stack runs the household hub's residency
profile on the Mac Studio beside the running hub, with every role green
on the board and Home still on its own supervisors. Nothing migrates
out of Home before that (STACK-16 is the migration and has its own
design pass in `home/docs/dev.md`).

Four blocks, each ending with an independent review of the block's
whole diff by a session that neither wrote nor accepted it:

| Block | Items | What exists at the end |
|---|---|---|
| A. The skeleton | STACK-01, STACK-02, STACK-03, DOCS-01 | A Bun service on one port with `/healthz` and `/api/docs`, the hardware probe and profile tiers, pinned engine downloads with checksums, the docs site skeleton |
| B. The contract | STACK-07 (design first), STACK-04, STACK-05, STACK-08 | Roles declared once and served by name, the model record with provenance, the supervisor with `spawned`, `managed` and `url` engines and identity headers, the operator login and role-scoped keys |
| C. The operator | STACK-06, STACK-09, STACK-10, STACK-11, STACK-12 | The governor, the event feed and Repairs, updates with rollback, first run and the board, Try it |
| D. The Studio | STACK-13, STACK-15, STACK-14 | Jobs and the managed ComfyUI, the launchd service, the first-day bench and the chosen profile |

Order inside a block follows the dependencies in the backlog; the
blocks are serial. B's design item (STACK-07, the role declaration and
wire contract) lands before any of B's code because every later item
imports it.

## Worktrees, base, landing

Each lane works in its own worktree of this repo:
`~/Developer/github.com/getmaipai/stack-codex` and `stack-c`, created by
the brief's first command if absent. A brief names its base: `main`, or
the lane's own previous branch when that branch has not landed yet (a
chain inside one lane, so the lane keeps moving overnight). Branches
are `<lane>/NN-<item>`. A lane never pushes and never touches `main`;
the coordinator reads each report (the hash, `git show --stat HEAD`,
the targeted tests, the gate's last line), reruns nothing it cannot
read, and lands green branches on `main` in queue order (fast-forward
or cherry-pick), then runs `check.sh` on `main` at the block's end and
pushes. A red report is a finding, never a fix.

The gate is `bash scripts/check.sh` from the worktree root. Until
STACK-01 lands it runs only the standards core; STACK-01 adds
`backend` install, `tsc --noEmit` and `bun test` in front of it, the
same order as `home/scripts/check.sh` lines 13 to 34. Live checks (a
real download, a real engine) are on-demand scripts named in the
brief, never part of the gate.

## Acceptance, in one place

Every item's acceptance is in the backlog; three rules apply on top.
A deterministic promise ("a checksum mismatch refuses the build", "a
revoked key is refused within one request") is proven by a test named
in the report. A universal claim ("every reply carries identity
headers") is accepted only with the enumeration of every route it
covers and the test per route. A live claim (a download completed, an
engine ran `--version`) is proven by the script's output pasted in the
report, with the engine build and a sanitized hardware line.

## What can go wrong, named now

- A lane invents a second layout because the scaffold brief left a
  choice open. The scaffold brief names every path; a later brief that
  needs a new folder says so.
- The hub's engine files carry hub-only imports (`@/db`, settings,
  notifications). A copied file keeps the logic and drops the import;
  the brief lists the imports to drop. A copy that pulls in a hub
  module is a red report.
- Session C's reading budget (300 lines) meets `dev.md` at 391 lines.
  Every Session C brief names the spans with `sed -n`.
- The Studio has not arrived. Block D's bench waits on it; blocks A to
  C do not.
